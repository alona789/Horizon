## [阿波罗飞行软件负责人玛格丽特·汉密尔顿逝世，享年 90 岁](https://news.mit.edu/2026/margaret-hamilton-computing-pioneer-dies-1007) ⭐️ 9.0/10

麻省理工学院仪器实验室软件工程部负责人、阿波罗导航计算机机载飞行软件开发主导者玛格丽特·汉密尔顿逝世，享年 90 岁，MIT News 与《卫报》均对此进行了报道。她因推动“软件工程师”这一称谓的普及而广为人知，并因此获得总统自由勋章。 汉密尔顿的离世意味着软件工程史上最具代表性的人物之一就此远去——在软件常被视为硬件附属品的年代，她帮助这门学科确立了严谨工程学科的地位。她在阿波罗项目中的工作证明，软件的可靠性可以关乎人的生死，这一理念如今支撑着从航空电子到医疗器械乃至各类现代安全攸关系统。 汉密尔顿领导的团队编写了阿波罗导航计算机的机载飞行软件，而该机器仅有约 4100 个硅集成电路、16 位字长和磁芯绳索只读存储器，性能大致相当于 1970 年代第一代家用电脑。她的团队还开发了优先显示与重启程序，正是这些程序在阿波罗 11 号下降过程中计算机被雷达数据过载时帮助任务得以继续。

## [Anthropic 发布 Claude Haiku 5.5，采用分级 token 定价并提供订阅 API 额度](https://www.anthropic.com/claude-haiku-5-5) ⭐️ 8.0/10

Anthropic 发布了 Claude Haiku 5.5，这是其小型、快速、低成本模型层的最新版本，同时引入了一套新的定价方案：当提示超过 100,000 个 token 时，计费单价会大幅提高。公司还表示将向 Max 和 Team 订阅用户按月发放 API 额度，其中 Max 5x 用户每月 100 美元、Max 20x 用户 200 美元，Team 订阅用户则可在成员间共享最多 500 美元额度。 Haiku 是开发者在跑高并发或智能体（Agent）工作负载时首选的廉价模型层，因此一个更强、更快且价格激进的小模型会直接改变所有 LLM 应用的成本账。附带在订阅中的 API 额度也模糊了消费级聊天订阅与付费 API 之间的界限，可能让个人开发者和小团队无需单独走 API 账单就能上线 AI 功能。 这次的分级定价颇为特殊：当提示不超过 10 万 token 时，输入为每百万 token 0.10 美元、输出为每百万 token 0.50 美元；一旦超过该阈值，则分别涨到每百万 token 0.50 美元和 2.50 美元，而且这一门槛只适用于 Haiku，不适用于 Sonnet 或 Opus。社区测试显示其质量较上一代有明显提升：simonw 在同一道 SVG 自行车任务上测得，“low”思考档耗时 7 秒、花费 0.0936 美分，而“max”档耗时 5 分 9 秒、花费 3.3826 美分；chriddyp 则报告该模型在 DataAnalyticsBench 考试中比 Haiku 4.5 便宜约 9 倍。

hackernews · sfkgtbor · 10月7日 18:01 · [社区讨论](https://news.ycombinator.com/item?id=49996437)

**背景**: Anthropic 的 Claude 产品线按能力分层：Opus 是能力最强的旗舰模型，Sonnet 是中端主力，Haiku 则是面向高吞吐或低延迟场景的最快、最便宜选择。这些模型的 API 定价通常按每百万输入/输出 token 计价，而 Anthropic 近期还加入了可调节的“思考”档位，让调用方用更多的推理时间和成本换取更好的答案。智能体类应用会把大量上下文反复喂回模型，因此对输入 token 的价格和上下文长度尤为敏感。

**社区讨论**: 评论区普遍认为 Haiku 5.5 是一次很实用的升级，但对新定价提出质疑：minimaxir 称 10 万 token 的门槛“低得离谱”，并指出只要做智能体类应用就很快会超过它；charlesabarnes 则欢迎订阅额度，认为这对上线 AI 功能是重大利好，但也担心这只是为缓和某些对用户不友好改动而给的安抚。simonw 的各思考档位基准测试和 chriddyp 的 DataAnalyticsBench 结果被广泛引用，作为其单位成本质量远胜 Haiku 4.5 的证据。

## [Chrome 重新加入 JPEG XL 支持，迈向多数浏览器覆盖](https://developer.chrome.com/blog/jpeg-xl-in-chrome) ⭐️ 8.0/10

Google 在 Chrome 开发者博客上宣布，Chrome 重新为 JPEG XL 图片格式提供支持，推翻了此前移除该格式的决定。结合即将上线的 Firefox 稳定版支持以及 Safari 已有的支持，JPEG XL 将在十月从仅 Safari 支持走向多数浏览器覆盖。 JPEG XL 此前最大的障碍正是最流行的浏览器不支持它，这严重限制了它在网页上的实际应用。Chrome 的反转意味着网站、CDN 和工具链可以更低风险地采用该格式，同时也削弱了 AVIF 作为唯一现代高保真图片格式的地位。 JPEG XL 同时支持有损与无损压缩，并具备渐进式解码能力，只需加载约 1% 的数据就能显示图像轮廓，在高保真摄影和无损场景中尤其受推崇。不过仍存在限制：在 CPU 性能严重受限的设备上编解码开销较大，且浏览器之外的生态支持（图像编辑器、系统预览与照片应用）仍不均衡。

hackernews · AshleysBrain · 10月7日 11:25 · [社区讨论](https://news.ycombinator.com/item?id=49991227)

**背景**: JPEG XL（JXL）由联合图像专家组（JPEG）与 Google、Cloudinary 共同开发，目标是在图像质量和压缩率上超越 PNG、JPEG 2000、GIF 和 WebP，并同时支持有损与无损编码。Chrome 团队曾在大约 2022 至 2023 年间以使用率低和维护负担为由在 Chromium 中弃用该格式，随后完全移除了支持。此次重新加入正是对这一决定的反转，也是社区长期呼声的结果。

## [论文质疑 OpenAI 的 Navier–Stokes 的 Lean 形式化](https://arxiv.org/abs/2610.08144) ⭐️ 8.0/10

一篇题为《Navier–Stokes Lost in Translation》的新 arXiv 论文指出，OpenAI 为其所宣称的 Navier–Stokes 爆破结果给出的 Lean 形式化，并未忠实对应原始的自然语言证明。作者具体声称，该 Lean 形式化证明与自然语言中关于 Navier–Stokes 方程解爆破的证明并不对应，暗示 OpenAI 可能并没有真正证明它所宣布的结论。 这直接挑战了迄今为止最引人注目的 AI 辅助数学成果之一——OpenAI 于 2026 年 9 月宣布由约一万个 AI 智能体组成的集群解决了 Navier–Stokes 爆破问题并给出了 Lean 形式化。如果这一批评成立，就会对 AI 生成的形式化证明如何被验证提出严峻问题，也会让人重新思考：机器可检验的证明，其可信度是否只取决于把它与原始数学命题相连接的那一步翻译。 争议的核心是翻译的忠实性，而非 Lean 证明本身的内部正确性：只要 Lean 内核接受了某个定理，该定理按其陈述就是正确的，因此真正的问题在于这个 Lean 陈述是否等价于原始命题，例如 Clay 数学研究所给出的表述。评论者还指出，自然语言的精确度低于 Lean，因此同一自然语言论证可以存在多种合法翻译；而这篇论文本身也存在争议——它究竟揭示了实质性的不匹配，还是仅仅指出了一次偷懒的、最小化的翻译。

hackernews · nill0 · 10月7日 15:24 · [社区讨论](https://news.ycombinator.com/item?id=49994145)

**背景**: Navier–Stokes 存在性与光滑性问题追问的是：描述流体运动的方程在三维空间中是否总存在光滑解，它是 Clay 数学研究所七大千禧年大奖难题之一。Lean 是一个开源的证明助理兼函数式编程语言，建立在归纳构造演算之上，其内核会逐步机械地检查证明的每一步。由于 Lean 处理的是形式化陈述而非自然语言文本，把自然语言证明翻译成 Lean 一直是形式化验证公认的薄弱环节，翻译阶段的错误或简化可能使最终形式化的东西证明的并非原本想要证明的定理。

## [HN 网友对 OpenAI 疑似证明 Barnette 猜想动情回应](https://simonwillison.net/2026/Oct/7/jake-boggan/) ⭐️ 8.0/10

Hacker News 网友 Jake Boggan 对 OpenAI 的 openai/math 仓库 Lean 文档中列为第 180 号问题的 Barnette 猜想疑似被证明一事作出了动情回应。Boggan 曾在这个问题上投入 24 年、数千小时的时间，他写道，听到问题已被解决，让他“莫名地感到一种遥远的悲伤”。 如果该证明成立，这将成为 AI 驱动数学发现的一个重要里程碑，因为 Barnette 猜想作为图论中的未解难题已经悬置了五十多年。这一反应也揭示了 AI 系统进入研究者倾注毕生精力领域时所带来的人性与情感层面的冲击。 该结论发布在 OpenAI 的 math 仓库中，该仓库公开由 OpenAI 内部模型生成的数学手稿及配套证明工件，并以公开研究问题评估模型；Lean 形式化提供了一个可由机器检验的验证层，但这本身并不能保证所陈述的结果与人们所理解的猜想完全一致。这则新闻本身只是引用了一条简短的 Hacker News 评论，而非一手技术资料，因此该证明在文中并未经过独立验证。
